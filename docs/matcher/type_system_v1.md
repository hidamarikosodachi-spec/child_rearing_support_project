# 子育てタイプ診断「わが家のこそだちタイプ」 タイプ体系 v1

> CEO決裁 2026-09-24（オーナー提案「診断を先に完成させ、タイプ別に記事を書く」を受諾）。
> 旧 `README.md` は「実親インタビュー後に実装」としていたが、**インタビュー（G1=20件）は読者不在で達成できていない**。
> 読者がいないから一次情報が取れず、一次情報がないから作れない、の循環を断つため**先に出す**判断に変更。
> 診断は**可逆**（気に入らなければ下げられる）・**追加コストゼロ**（静的サイト）なので、速く動かす対象。

## 1. なぜ診断なのか（事業上の役割）

現状のボトルネックは品質ではなく**リーチと読者基盤**（note 総PV 230・フォロワー1・Threads フォロワー0）。
記事は「読んだ人にしか効かない」が、診断には記事に無い3つの性質がある。

1. **共有される**：人は診断結果を人に見せる。フォロワー0でも、結果ページのURLは動く。
2. **入口が1つになる**：全SNSの導線を「まず診断」に集約でき、バラバラの投稿が1本の線になる。
3. **タイプが記事の器になる**：8タイプ＝8本の連載記事。書く理由と読む理由が同時に生まれる（オーナー提案の相乗効果）。

**やらないこと**: 正解を決める／親を格付けする／「あなたは○○型だから△△すべき」と指示する。
本診断は **現時点の傾向のスナップショット**であり、どのタイプも等価。ランキング表示はしない。

## 2. 軸：6軸 → 3軸に絞る（タイプ化のため）

`axes_v0.md` の6軸（R/S/I/E/P/C）は**分析には正しいが、タイプ名にすると 64 通りで覚えられない**。
MBTI が機能しているのは「4文字で自分を語れる」からなので、**タイプ化は3軸8タイプ**に絞る。

| 使う軸 | 略号 | 両極 | 絞った理由 |
|---|---|---|---|
| 主導権 | I | **導く**（I+） ⇔ **委ねる**（I−） | 親が最も自覚しやすく、理論の分かれ目そのもの |
| 構造性 | S | **整える**（S+） ⇔ **流れる**（S−） | 生活実感に直結（毎日の時間割）・回答がぶれにくい |
| 応答性 | R | **寄り添う**（R+） ⇔ **見守る**（R−） | 「抱っこしすぎ？」「待つべき？」という最頻の悩みの軸 |

**残る3軸（E 評価観 / P 早期化 / C 関係性）はタイプ名に使わず、結果ページの「サブ傾向」として1〜2行で添える。**
捨てるのではなく、タイプの粒度を上げずに個別性を出すために使う。

## 3. 8タイプ（v1・仮称）

命名はブランド（ひだまり＝場所・自然・温度）に合わせ、**人物の格付けではなく「場の風景」**で表す。
どのタイプにも「強み」と「つまずきやすい点」を必ず対で書く（片方だけにしない）。

| # | 軸 | タイプ名 | 一行の像 | 強み | つまずきやすい点 | となりに置く理論 |
|---|---|---|---|---|---|---|
| 1 | I+ S+ R+ | **灯台** | 先に光を置いて、そばにいる | 見通しと安心を同時に渡せる | 先回りしすぎて子の出番が減る | ボウルビィ／佐々木正美 |
| 2 | I+ S+ R− | **畑** | 種をまき、手をかけすぎずに育てる | 環境を整えて待てる | 「待つ」が「放置」に見える日がある | モンテッソーリ／ピクラー |
| 3 | I+ S− R+ | **たき火** | その日の風向きで、火を囲む | 状況に合わせて動ける・情が濃い | 基準が日によって変わり子が読めない | NVC／アドラー |
| 4 | I+ S− R− | **山道** | 先を歩き、ときどき振り返って待つ | 挑戦を促しつつ手は出しすぎない | 子のペースより道のりを優先しがち | 成長マインドセット／ヴィゴツキー |
| 5 | I− S+ R+ | **縁側** | 決まった場所で、いつでも隣に | 安心の土台が厚い・子が戻ってこられる | 子が離れていく時期に寂しさが出る | ボウルビィ（安全基地）／汐見稔幸 |
| 6 | I− S+ R− | **本棚** | 並べておいて、選ぶのは子 | 選択の自由と秩序を両立できる | 子の「今」の気持ちを拾い損ねる | モンテッソーリ／倉橋惣三 |
| 7 | I− S− R+ | **小川** | 流れに沿って、一緒に揺れる | 子の世界に入っていける・遊びが豊か | 生活リズムが崩れて親が疲れる | 汐見稔幸／遊びの理論 |
| 8 | I− S− R− | **野原** | 広く開けて、好きに走らせる | 子の自律性が育ちやすい | 危険と自由の線引きが後手になる | ピクラー／サドベリー（両論併記） |

> すべてのタイプ説明に「**この傾向は子の年齢・第二子・その日の余裕で変わります**」を明記する（固定化の防止）。

## 4. 質問（12問 → 9問へ）

`questions_v0.md` の12問のうち、使う3軸ぶん（R/S/I 各2問＝6問）を核にし、
**判定が割れやすい軸に3問目を足して 9問**（各軸3問）にする。E/P/C の質問は「サブ傾向」用に**任意の追加3問**として最後に置く（スキップ可）。
- 所要 **約2分**（離脱を防ぐ上限）。5段階リッカートは v0 のまま。
- 中立が続いた場合は「まんなか」を明示し、近い2タイプを両方提示する（無理に1つへ寄せない）。

## 5. 実装（MVP・静的サイト）

| 項目 | 決定 | 理由 |
|---|---|---|
| ホスティング | **GitHub Pages**（本リポジトリ） | 無料・すでに GitHub 上・追加アカウント不要 |
| 構成 | HTML + CSS + 素の JS 1ファイル | ビルド不要・私が保守できる・壊れにくい |
| 判定 | **完全にブラウザ内で計算** | サーバー無し＝個人情報を一切集めない（同意取得も不要） |
| 結果の共有 | タイプごとの固定URL（例 `/type/engawa/`）＋ X/Threads/LINE 共有ボタン | 「結果を見せる」が拡散の起点 |
| 記事への導線 | 結果ページ下部に **そのタイプ向けの note 記事**＋連載一覧 | 診断 → 記事 の一方通行を作る |
| 計測 | 回答分布は取らない（MVP）。**結果ページ→note のクリック**だけ note 側PVで見る | 収集を増やすと同意・保守コストが増える |
| 任意 | 結果ページ末尾に既存の Google Form（感想）への導線 | 読者不在で取れなかった一次情報を、ここで少しずつ拾う |

## 6. 記事計画（在庫切れ 10/9 の次の柱）

連載「となりの考え方」は第9回まで在庫あり。**第10回以降をタイプ別8本**に充てる。

| 回 | 記事 | 対応タイプ |
|---|---|---|
| 予告編 | 「わが家の子育て、どの風景に近い？」＝診断の告知記事 | 全体 |
| 10〜17 | 各タイプの記事（強み・つまずき・となりの理論・明日試せること） | 灯台/畑/たき火/山道/縁側/本棚/小川/野原 |

既存の連載記事（01〜10）は各タイプの「となりに置く理論」として**内部リンクで再利用できる**＝過去記事が生き返る。

## 7. やらない・保留

- 50理論 × 6軸の推奨エンジン（`recommendation_v0.md`）は **MVP では使わない**。専門家レビュー未了のため、
  「あなたに合う理論を1位から並べる」形は出さない。**「となりに置いてみる理論を2つ紹介する」**に留める。
- × グループ（ヨコミネ式・七田式・公文式）は v0 決定どおり**推奨しない**（両論併記の対象としてのみ言及可）。
- 有料化はしない（診断・記事とも無料）。収益は別線で判断する。

## 8. リスクと歯止め

- **「決めつけられた」と感じさせる**risk → 全タイプ等価・ランキング無し・「スナップショット」明記・両論併記。
- **診断を出しても広まらない** risk → 診断は拡散の**器**であって起点ではない。起点（人に直接届ける＝note 誠実接触）は別途必要。
  **診断単体で読者が増えると期待しない**こと。
- **作り込みすぎて出ない** risk → MVP は 9問＋8タイプ＋静的ページのみ。回答保存・アカウント・推奨エンジンは入れない。
