# 自前サイトの文章 v1（提案）— 検索から来た人に書く

> `hidamari-kosodachi.com/kosodachi/<記事>` に載せる記事の方針。
> Threads/IG（物語）とも note（連載）とも**役割が違う**ので、書き方を分ける。

## 1. 誰に書くか

**夜23時、スマホで「子供 怒鳴ってしまう 後悔」と検索した人。**

- 子どもを寝かしつけたあと、後悔したまま検索している
- 読みたいのは物語でも理論でもなく、**「自分だけじゃないのか」と「明日どうするか」**
- 3秒で「ここに答えがありそうか」を判断して、無ければ戻る
- 落ち込んでいるので、責められたら閉じる

**note の読者（連載を追ってくれる人）とは別人**。関係がゼロの状態で、いきなり来る。

## 2. 3媒体の役割分担

| | 読者の状態 | 書き方 | 目的 |
|---|---|---|---|
| **Threads / IG** | 流し見している | **物語**（場面→ずれ→余韻） | 心を動かす・存在を知ってもらう |
| **note 連載** | 腰を据えて読む | **説明体**（こんな日→ある人はこう考えた→明日試せること） | 考え方を渡す・信頼を作る |
| **自前サイト** | 困って検索している | **実用体**（答え先出し→やること→なぜ→ただし） | 即座に助ける・見つけてもらう |

## 3. 記事の型（テンプレート）

```
# ＜検索語をそのまま含むタイトル＞
　例：「怒鳴ってしまった」と後悔する夜に — 今日できることと、明日からのこと

＜リード 2〜3行＞
　いま知りたいことへの答えを、最初に書く。前置きをしない。
　例：怒鳴ってしまった日は、やり直せます。取り返しがつかないことではありません。
　　　今夜できることと、次に同じ場面が来たときのことを書きます。

## 今夜できること（3つ・箇条書き）
　いますぐ実行できる具体だけ。理屈は書かない。

## なぜそうなるのか
　ここで初めて理論を1つだけ。名前は1回、説明は3行まで。

## それでも、うまくいかない日のために
　できない日を責めない。「毎日できなくていい」を明言する。

## こういうときは、相談していい
　医療・支援の窓口。必ず入れる（ブランドの約束）。

---
＜診断への導線（控えめに1回だけ）＞
```

## 4. トーンのルール

**note・SNS と共通で守るもの**
- 断定しない／親を責めない／NG語を使わない（絶対・必ず・○歳までに・天才・手遅れ）
- 医療の境界を必ず置く
- 改行は「1行だけ読んで意味が通る」位置で切る（[[feedback-line-breaks]]）

### 語り方（オーナー修正 2026-09-30・最重要）

読むのは**落ち込んでいる人**。指示・禁止の言葉は冷たく響く。**呼びかけと保証**で書く。

| × 冷たい（禁止形・指示形） | ○ 採用（呼びかけ・保証） |
|---|---|
| 眠っている子に、ひとこと言っておく | 眠っている子に、ひとこと**伝えましょう** |
| 理由を説明しない | 理由は**説明しなくても大丈夫です** |
| 自分を採点しない | **自分を責めないでください** |
| 声の大きさについてだけ謝って、そこで止めます | 声の大きさについてだけ謝る。**それだけで、子どもには伝わります** |
| 謝らなかった日があっても、翌朝いつもどおりに接すれば十分です | 謝れない日が**あっても大丈夫です**。翌朝いつもどおりに接すれば、**それで十分伝わります** |

### 口調は「カウンセラーが相談者に伝えるように」（オーナー指示 2026-09-30）

- **主語を省かない。** 誰の何が変わるのかを必ず書く。
  × 「それで回復は始まります」（誰の回復か分からない）
  ○ 「それだけで**子どもの心は**いつもどおりに戻ります」
- **抽象語を使わない。** 「回復」「改善」「関係性」より、**具体的に何がどうなるか**。
- **落ち着いて言い切る。** 迷っている人に、揺れた言い方を返さない。
- **相手（あなた）と子ども、どちらの話かを毎回はっきりさせる。**

| × 主語が消えている | ○ 主語を出す |
|---|---|
| 一度の出来事で、それまで積み上げたものが消えることはありません | 一度の出来事で、**あなたが**これまで積み重ねてきたものが消えることはありません |
| 違うのは子どもの行動ではなく、こちらに残っている力のほうです | 違うのは子どもの行動ではありません。そのとき、**あなたに**残っていた力の量です |
| 「やってしまった」と思っている時点で、戻ろうとしています | 「やってしまった」と感じている時点で、**あなたはもう**戻ろうとしています |
| 今日できなかったことを思い返し始めると、夜が長くなります | 今日できなかったことを思い返し始めると、**あなたの夜は**どんどん長くなります |

**使わない比喩**: 点数・採点・合格/不合格など、**子育てを評価される行為として扱う言い方**
（「正解を決めない」というメディアの立場と矛盾するため）。

**原則**
1. **見出しを禁止形にしない**（「〜しない」→「〜しなくても大丈夫です」「〜しましょう」）
2. **文を「保証」で終える**（〜で伝わります／〜で十分です／〜で大丈夫です）
3. **手順の説明で終わらせず、効果を約束する**。読者が知りたいのは「やり方」より「これで足りるのか」
4. 「〜してください」は強いので、**救いになる場面だけ**使う（例：自分を責めないでください）
5. **言い切ってよい**。ここは note と違い、迷っている人に断定を渡す場面（ただし子どもの発達を断定するのは不可）

> **注意**: オーナーからの指摘は「説明」であって「本文案」とは限らない。
> 説明としてもらった言い回しを、そのまま記事に入れない（実際に 2026-09-30 に入れてしまい、削除した）。
> 修正の**意図**（禁止形をやめる・保証で終える）を汲んで、本文は自分で書き直す。

**自前サイトだけのルール**
1. **答えを最初に書く。** 検索の人は結論を待てない。物語で始めない。
2. **見出しだけで筋が通るようにする。** 本文を読み飛ばしても意味が取れる。
3. **箇条書きを使う**（note ではあまり使わない）。スマホで拾い読みできる形に。
4. **理論は1記事1つまで。** 名前は1回だけ。「モンテッソーリが」ではなく「ある保育の考え方では」で足りる場面も多い。
5. **1記事 1,200〜1,800字。** 連載より短く。読み切れる量。
6. **物語形式は使わない**（[[writing_voice_v1]] は Threads/IG 限定）。
7. **「あなた」を使ってよい**（note では避け気味だが、検索記事は1対1で話す）。

## 4.5 制作の流れ（2026-09-30 構築）

```
docs/site/articles/<slug>.md        ← 記事の正本（Obsidianで読める・私が執筆）
        ↓ python3 scripts/build_site_articles.py
web/kosodachi/<slug>.html           ← 公開ページ（OGP・構造化データ・共通CSS）
        ↓ wrangler pages deploy
https://hidamari-kosodachi.com/kosodachi/<slug>
```

- front-matter の `status` が **published** のものだけ公開される（`draft` は生成されない）
- `--all` を付けると draft も生成（オーナー確認用）
- 公開すると `build_matcher_pages.py` が **sitemap に自動で追加**する
- 記事ページには**構造化データ（Article）**を入れてある（検索での表示に効く）

## 6. note との重複を避ける

同じ内容を両方に載せない（検索評価が割れる）。

| note | 自前サイト |
|---|---|
| 理論を軸にした読みもの（「アドラーの考え方をとなりに置く」） | 悩みを軸にした実用記事（「怒鳴ってしまった夜にすること」） |
| 連載として積む | 単体で完結する |

**関連する note 記事へは、自前サイトからリンクする**（逆はしない。検索評価を自前サイトに集めるため）。
