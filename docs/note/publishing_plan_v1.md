  崩れる兆しが出たら、本数ではなく**私が自分でペースを落として報告する**。

## なぜ受けるか／同時に正直に言っておくこと

- **可逆**（いつでも戻せる）で、追加コストは私の執筆時間だけ。オーナーの負担は増えない → 速く動く対象。
- note には「新着」やタグからの内部回遊があるので、**本数を増やすと露出面は増える**。
- ただし現状のボトルネックは**リーチ（読者がいないこと）**であって供給量ではない。
  **3倍書いても3倍読まれるとは限らない**。ここは期待値を上げすぎないでおく。
- そのため **測る**: 「1本あたりPV」を週3化の前後で比較する（下記）。

## タグ＝note のお題に毎回応募する（CEO判断 2026-10-02・オーナー了承）

note の**常設お題はハッシュタグを付けるだけで応募**になり、お題ページに並ぶ（無料の打席）。
**9つのタグのうち2枠を、必ずお題に充てる。**

1. **#子育ての悩み**（98,392件）＝固定
2. その回に合うお題を1本 — **#育児日記**（177,479）／**#子どもの成長記録**（55,073）／
   **#子どもに教えられたこと**（43,703）／**#ワーママあるある**／**#ワーパパあるある**

お題ではない自作タグ（#育児ママ #育児パパ など）は、この2枠を圧迫するなら外す。
**内容と合わないお題は付けない**（数字のために嘘をつかない）。

期間限定コンテストは**育児系が開いたときだけ**応募する（書き下ろし1本まで）。
開催状況は `.venv/bin/python scripts/note_contests.py` で週次に確認する。
創作大賞は不採用（応募34万件・長編向き・週3hと両立しない）。

**判定 10/24**: お題タグを変えた記事と、それ以前の記事で PV に差が出たか。差がなければ外す。

## 公開後の告知（オーナー指示 2026-10-01）

note を公開したら、**毎回 Instagram のストーリーで告知する**。

```bash
.venv/bin/python scripts/promote_note_article.py docs/note/articles/<記事>.md
cd web && npx wrangler pages deploy . --project-name hidamari-kosodachi --commit-dirty=true
```
→ ストーリー画像を生成してサイトに置き、スマホ用URLと貼るリンクを出力する。
**オーナーの作業は1分**（保存 → ストーリー投稿 → リンクスタンプ）。

リンクスタンプは API で貼れないため、ここだけ手作業。フィード投稿は週1まで（[[feedback-note-to-instagram]]）。

## 運用ルール

1. 公開前に必ず `scripts/format_note_linebreaks.py` を通す。
2. 入稿は `scripts/note_article_draft.py`（HTML貼付・リンク保持・見出し画像）。
3. タグは9個（`note_tags:` に明記）。実績のある汎用タグを軸にする。
4. 公開後、記事 front-matter に `published` / `published_url` を記録し、台帳（[[posting_schedule]]）を同期する。
5. **Threads の返信リンク（T101）を、公開した記事に合わせて更新する**。記事が増えるほど、この対応表が効く。
