# 到達の目標：IG リール 1本500回／Threads 1投稿1000回（オーナー指示 2026-11-09）

> オーナー指示：「IG の再生回数500回る内容、Threads も1000回る内容を模索。当分の目標として、**達成まで試行錯誤を繰り返す**」。
> 実行はすべて私（CEO）に任された（企画・ドラフト・投稿・承認）。オーナーの作業は発生させない。

## 目標と達成の定義

| 媒体 | 目標 | 達成の定義（偶然を除く） | 現状（2026-11-09） |
|---|---|---|---|
| Instagram リール | 1本 **500回** 再生 | 500 超えが出る → **直近5本中3本**が 500 超え | 最大 **151**／中央値 28／到達 0本 |
| Threads | 1投稿 **1,000 views** | 1,000 超えが出る → **直近6投稿中2本**が 1,000 超え | 最大 **408**（6/22）／直近10投稿の最大 **139**／到達 0本 |

- 1本の当たりは偶然がありうる。**再現するまで「型」とは呼ばない**。
- 再生数は投稿から数日かけて伸びる。**判定は投稿7日後**に行う（IG は投稿後48時間で大半が決まるので、速報は2日後に見る）。
- 観測: `.venv/bin/python scripts/ig_reel_insights.py`（IG 別）／`scripts/threads_insights.py`／`insights_all.py`。

## 守る柵（試行錯誤でも外さない）

- **BAN リスクのある手段は使わない**：フォロー・いいね・コメントの機械的な大量実行、他アカウントの自動操作、購入フォロワー／再生、エンゲージメント誘導の定型文（「いいねで教えて」等）。
- 売り込まない（note 接触と同じ）。医療・発達の断定をしない。教具・高額商品を煽らない。
- 投稿前の重複確認（IG／Threads は API で削除できない）。
- 数字・研究は原典で照合してから書く。**再生数のために事実を盛らない**。
- 文章ルール（主語を省かない／1行で読める位置の改行／オチをつけない／感情語を名指ししない）。

## 実測から立てる仮説（これが出発点）

### IG リール
実測（ig_reels.md・11/9）：

| 形式 | 本数 | 再生 | 平均視聴 |
|---|---|---|---|
| 文字だけのスライド（10/18〜11/2） | 約10 | 7〜123（中央値 約24） | 0.8〜3秒（長い2本は26〜32秒で、見た人は読んでいる） |
| **漫画リール（11/4・11/8）** | 2 | **151・150**（投稿から約1日） | **6〜7秒** |
| 同日 11/4 の文字だけ（朝）／漫画（夜） | 1／1 | 36／**151** | 1.1／6.8 |

- **H-IG1：絵（場面）で止めると、文字だけの 5倍近く再生される。** 11/4 は同日に両方を出した比較で、同じ向き。まず **この型を増やして再現性を見る**。
- **H-IG2：22秒中の平均視聴は6〜7秒＝約3割。** 長さを 12〜15秒に詰めると維持率が上がり、配信が広がる可能性。
- **H-IG3：題材。** Threads で強かった「親が後ろめたい」題材（叱り方・保育園の送り・動画・赤ちゃん返り）を絵にする。
- **H-IG4：冒頭1秒の言葉。** 現状は疑問形の見出し。「当事者の一言（セリフ）」のほうが止まるか。
- **H-IG5：投稿時刻。** 11/4 夜20時が 151、11/8 昼 12:30 が 150。差は見えない。**17〜19時（夕方の隙間時間）**を試す。
- **H-IG6：音。** API からは流行の音を付けられない。**アプリで手動投稿**する回を1本だけ試す（オーナー1分・1回だけ頼む）。
- 保留：実写の手元・子どもの場面は、リサーチ上いちばん強い（保育士バンク 中央値1万）が、**顔・子どもの映像はオーナー判断が要る**。漫画で 500 に届かなかった場合の次の手。

### Threads
実測（11/9 時点 約50投稿）：

- 上位：叱り方 408／保育園の送りで泣く 263／動画をやめられない 239／赤ちゃん返り 229／うまくいった接し方① 209／怒鳴ったあと 209。**全部「自分が悪かったかも」と親が思う題材**。
- 直近10投稿は 16〜139。**1,000 は過去最高の約2.5倍**で、いまの型の延長では届かない。
- フォロワーは1〜3人。**views の大半は推薦（おすすめ）経由**＝フォロワー数でなく**1行目の引き**で決まる。

- **H-TH1：打席を増やす。** 隔日 → **毎日**。分布の裾（当たり）に当たる回数が2倍になる。
- **H-TH2：1行目で全部分かる書き出し。** 現状は「夕方5時、リビングから…」の場面描写。「**怒鳴ったあと、寝顔に『ごめんね』と言った。**」のように**先に感情の結果から入る**型を試す。
- **H-TH3：上位題材の再挑戦（別角度）。** 叱り方／保育園の送り／動画／赤ちゃん返りを、**別の場面**で書き直す。題材が当たりか、偶然かを切り分ける。
- **H-TH4：短く。** 上位の多くは短文。**100字前後**の短い投稿を混ぜて比べる。
- **H-TH5：投稿時刻。** 12:00 固定 → **朝 7:30／夜 21:00** を試す（Actions に時刻を足す）。
- **H-TH6：返信欄に続きを置く**（1返信目）。読了・滞在を増やせるか。リンクは入れない。

## 実験の進め方（ルール）

1. **1回に動かす変数は1つ**。残りは固定する。
2. **同条件3本**で一次判定。中央値が前の型の2倍以上＝採用。1本の差は誤差とみなす。
3. 負けた型は理由を一行で残して**やめる**（惰性で続けない）。
4. **毎週日曜**の週次レビューで、この表を更新する（Claude が回す）。IG は**投稿2日後**に速報も見る。
5. 毎週**1つは新しい試み**を入れる（[[feedback-chase-user-demand]]）。

## note の見出し画像（NT-1・オーナー指示 2026-11-09）

> 「Gemini で note のアイキャッチも作って、変わるか検証してほしい」。**IG・Threads の目標とは別の、記事の到達を見る実験**。

- **比べるもの**：絵＋タイトル帯（`scripts/note_eyecatch_illust.py`・Gemini）vs 従来の文字だけ（`note_thumbnail.py`）。
- **方法**：新規記事を**交互**に「絵あり／文字のみ」で出す（公開済み記事の差し替えは、本文が3重になった事故（10/14）に近い操作でリスクが高いので**やらない**）。ジャンル・口調はそろえる（いまは G2 困りごと）。
- **見る指標**：記事ごとの PV（公開3日後・7日後）とスキ。`note_experiment.py` の表に「見出し」列を足して突き合わせる。
- **判定**：各6本（12日分）で中央値を比べ、**2倍以上**なら採用。**1本あたりの PV が10前後と小さく、ノイズが大きい**ので、差が出なければ「見出し画像では動かない」と結論して、次の手（題名・冒頭）に移る。
- **柵**：絵のなかに文字・ロゴを入れさせない（崩れるため）。タイトルは PIL で乗せる。
